# Understanding `agent/persistence.py`

The [`agent/persistence.py`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/agent/persistence.py>) file allows the application to save an agent conversation to disk and load it again later.

Without persistence, a `Session` exists only in memory. When the program exits, its messages, turn count, and usage information disappear.

Persistence provides:

- Saving a session
- Listing saved sessions
- Resuming a saved session
- Creating checkpoints
- Restoring a checkpoint

The basic idea is:

```text
Live Session
     |
     v
SessionSnapshot
     |
     v
JSON file on disk
     |
     v
SessionSnapshot
     |
     v
New live Session
```

## 1. The two main classes

The file defines:

```python
class SessionSnapshot
class PersistenceManager
```

They have different responsibilities:

| Class | Responsibility |
|---|---|
| `SessionSnapshot` | Represents the serializable state of a session |
| `PersistenceManager` | Saves, loads, and lists snapshots |

`SessionSnapshot` is the data. `PersistenceManager` performs the file operations.

## 2. What is a `SessionSnapshot`?

`SessionSnapshot` is a dataclass containing the important state of an active session:

```python
@dataclass
class SessionSnapshot:
    session_id: str
    created_at: datetime
    updated_at: datetime
    turn_count: int
    messages: list[dict[str, Any]]
    total_usage: TokenUsage
```

It stores:

### `session_id`

The unique identifier of the session.

This is generated by [`Session`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/agent/session.py>) using a UUID and is used as the saved session filename.

### `created_at`

The time when the session originally started.

### `updated_at`

The most recent time the session state was updated.

### `turn_count`

The number of agent-loop turns completed.

### `messages`

The conversation messages, including user, assistant, and tool messages.

Example:

```json
[
  {
    "role": "user",
    "content": "Read my project files"
  },
  {
    "role": "assistant",
    "content": "I will inspect the project."
  }
]
```

### `total_usage`

The accumulated token usage represented by [`TokenUsage`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/client/response.py>):

```python
TokenUsage(
    prompt_tokens=100,
    completion_tokens=50,
    total_tokens=150,
    cached_tokens=0,
)
```

This allows the restored session to retain its usage statistics.

## 3. Converting a snapshot to JSON data

The `to_dict()` method converts a `SessionSnapshot` into a dictionary:

```python
def to_dict(self) -> dict[str, Any]:
```

It converts timestamps to ISO strings:

```python
"created_at": self.created_at.isoformat()
"updated_at": self.updated_at.isoformat()
```

It also converts token usage into a dictionary:

```python
"total_usage": self.total_usage.__dict__
```

The resulting data can be written safely using `json.dump()`.

Conceptually:

```text
SessionSnapshot object
        |
        v
Plain dictionary
        |
        v
JSON file
```

## 4. Rebuilding a snapshot from JSON

The `from_dict()` class method performs the reverse operation:

```python
@classmethod
def from_dict(cls, data: dict[str, Any]) -> SessionSnapshot:
```

It:

1. Reads the saved session ID
2. Converts ISO timestamp strings back to `datetime`
3. Restores the turn count
4. Restores the message list
5. Recreates the `TokenUsage` object

For example:

```python
snapshot = SessionSnapshot.from_dict(saved_data)
```

The result is a real `SessionSnapshot`, not just a plain dictionary.

## 5. `PersistenceManager` initialization

The manager determines where saved data should live:

```python
self.data_dir = get_data_dir()
```

`get_data_dir()` comes from [`config/loader.py`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/config/loader.py>) and returns the application data directory.

Two subdirectories are created:

```text
<application data directory>/ai-agent/sessions
<application data directory>/ai-agent/checkpoints
```

The constructor creates them if necessary:

```python
self.sessions_dir.mkdir(parents=True, exist_ok=True)
self.checkpoints_dir.mkdir(parents=True, exist_ok=True)
```

It also applies restrictive directory permissions:

```python
os.chmod(self.sessions_dir, 0o700)
os.chmod(self.checkpoints_dir, 0o700)
```

The intention is that only the current user can access saved conversation data.

## 6. Saving a session

The `save_session()` method writes a snapshot to the sessions directory:

```python
def save_session(self, snapshot: SessionSnapshot) -> None:
```

The filename is based on the session ID:

```text
<sessions directory>/<session_id>.json
```

The method:

1. Converts the snapshot with `to_dict()`
2. Writes formatted JSON
3. Restricts the file permissions

```python
with open(file_path, "w", encoding="utf-8") as fp:
    json.dump(snapshot.to_dict(), fp, indent=2)

os.chmod(file_path, 0o600)
```

`0o600` means the file is intended to be readable and writable only by the owner.

## 7. How `/save` uses it

The `/save` command is implemented in [`main.py`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/main.py>).

It collects state from the active session:

```python
session_snapshot = SessionSnapshot(
    session_id=self.agent.session.session_id,
    created_at=self.agent.session.created_at,
    updated_at=self.agent.session.updated_at,
    turn_count=self.agent.session.turn_count,
    messages=self.agent.session.context_manager.get_messages(),
    total_usage=self.agent.session.context_manager.total_usage,
)
```

It then saves the snapshot:

```python
persistence_manager.save_session(session_snapshot)
```

The user can later use the printed session ID with `/resume`.

## 8. Loading a saved session

The `load_session()` method takes a session ID:

```python
def load_session(self, session_id: str) -> SessionSnapshot | None:
```

It looks for:

```text
<sessions directory>/<session_id>.json
```

If the file does not exist:

```python
return None
```

If it exists, the JSON is read and converted back into a `SessionSnapshot`.

## 9. How `/resume` works

The `/resume` command performs these steps:

```text
1. Receive a session ID
2. Load the snapshot from disk
3. Create a new Session
4. Initialize its tools and services
5. Restore session metadata
6. Re-add saved messages to the context manager
7. Close the old session
8. Replace it with the restored session
```

The session metadata is restored:

```python
session.session_id = snapshot.session_id
session.created_at = snapshot.created_at
session.updated_at = snapshot.updated_at
session.turn_count = snapshot.turn_count
session.context_manager.total_usage = snapshot.total_usage
```

Messages are restored according to their roles:

```python
if msg["role"] == "user":
    session.context_manager.add_user_message(...)
elif msg["role"] == "assistant":
    session.context_manager.add_assistant_message(...)
elif msg["role"] == "tool":
    session.context_manager.add_tool_result(...)
```

System messages are skipped because the new context manager creates the current system prompt again.

The restored session is then installed into the running agent:

```python
self.agent.session = session
```

## 10. Listing saved sessions

The `list_sessions()` method scans every JSON file in the sessions directory:

```python
def list_sessions(self) -> list[dict[str, Any]]:
```

It returns summary information rather than loading complete conversations:

```python
{
    "session_id": "...",
    "created_at": "...",
    "updated_at": "...",
    "turn_count": 5,
}
```

The sessions are sorted by `updated_at`, with the most recently updated sessions first.

The CLI displays this information with:

```text
/sessions
```

This lets the user find a session ID before using:

```text
/resume <session_id>
```

## 11. What is a checkpoint?

A checkpoint is another saved copy of a session at a particular point in time.

Normal saved sessions use the session ID as the filename:

```text
<sessions directory>/<session_id>.json
```

Checkpoints use a unique ID containing the session ID and timestamp:

```text
<checkpoints directory>/<session_id>_YYYYMMDD_HHMMSS.json
```

This allows multiple saved states for the same session.

For example:

```text
abc123_20260924_001530.json
abc123_20260924_002100.json
```

Each file represents a different point in the conversation.

## 12. Creating a checkpoint

The `save_checkpoint()` method:

```python
def save_checkpoint(self, snapshot: SessionSnapshot) -> str:
```

It:

1. Creates a timestamp
2. Builds a checkpoint ID
3. Writes the snapshot to the checkpoints directory
4. Restricts file permissions
5. Returns the checkpoint ID

The CLI creates one using:

```text
/checkpoint
```

The returned checkpoint ID is needed for restoration.

## 13. Restoring a checkpoint

The `load_checkpoint()` method works like `load_session()` but uses the checkpoints directory:

```python
def load_checkpoint(self, checkpoint_id: str) -> SessionSnapshot | None:
```

The CLI restores it with:

```text
/restore <checkpoint_id>
```

The restoration flow is almost the same as `/resume`:

1. Load the checkpoint snapshot
2. Create and initialize a new session
3. Restore metadata
4. Restore messages
5. Close the old client and MCP manager
6. Replace the active session

## 14. Session versus checkpoint

| Feature | Saved session | Checkpoint |
|---|---|---|
| Command | `/save` | `/checkpoint` |
| Directory | `sessions` | `checkpoints` |
| Filename | Session ID | Session ID plus timestamp |
| Purpose | Save the current session | Save a point-in-time version |
| Multiple versions | Later save overwrites the same session file | Multiple checkpoints can coexist |
| Restore command | `/resume <session_id>` | `/restore <checkpoint_id>` |

## 15. Example workflow

### Save a session

```text
[user]> Explain this project
[assistant]> ...
[user]> /save
```

The application writes a JSON file and prints:

```text
Session saved: <session_id>
```

### List sessions

```text
[user]> /sessions
```

The application prints available session IDs.

### Resume later

```text
[user]> /resume <session_id>
```

The conversation messages and usage information are restored into a new active session.

### Create a checkpoint before a risky operation

```text
[user]> /checkpoint
```

Then, if necessary:

```text
[user]> /restore <checkpoint_id>
```

The agent returns to the saved point.

## 16. What persistence does not save

The snapshot saves conversation-related state, but it does not serialize every runtime object.

It does not directly save:

- The live LLM client connection
- Running MCP processes
- Tool class instances
- Hook process state
- Loop detector history
- The complete `Config` object

When restoring, the application creates and initializes a fresh `Session`. This recreates the runtime services using the current configuration, then restores the saved conversation data.

This is important because network connections and Python objects should be recreated rather than serialized into JSON.

## 17. Security and file permissions

Saved sessions can contain:

- User messages
- Assistant responses
- Tool results
- Project paths
- Potentially sensitive conversation details

The persistence manager attempts to protect them by applying:

```text
Directories: 0o700
Files:       0o600
```

This is intended to restrict access to the owner on systems that support Unix-style permissions.

## 18. Error behavior

The `load_session()` and `load_checkpoint()` methods return `None` when the requested file does not exist.

The current implementation does not catch errors from:

- Invalid JSON
- Missing required snapshot fields
- Invalid timestamp values
- Invalid token usage values
- File permission failures

Those errors can therefore propagate to the caller. This makes corrupted persistence data visible instead of silently treating it as a valid empty session.

## 19. Complete architecture

The persistence flow is:

```text
Active Session
      |
      | /save or /checkpoint
      v
Build SessionSnapshot
      |
      v
Convert to dictionary
      |
      v
Write JSON file
      |
      | /resume or /restore
      v
Read JSON file
      |
      v
Rebuild SessionSnapshot
      |
      v
Create and initialize new Session
      |
      v
Restore metadata and messages
      |
      v
Continue conversation
```

## Summary

[`agent/persistence.py`](<d:/Gen AI/CLI agent.worktrees/ai-coding-agent-main/agent/persistence.py>) gives the application durable conversation storage.

Its responsibilities are:

```text
Capture session state
  -> Convert it to JSON
  -> Save sessions and checkpoints
  -> Load them later
  -> Rebuild a usable session state
```

`SessionSnapshot` defines what is saved. `PersistenceManager` defines how it is saved and restored. Together, they power the CLI commands `/save`, `/sessions`, `/resume`, `/checkpoint`, and `/restore`.
